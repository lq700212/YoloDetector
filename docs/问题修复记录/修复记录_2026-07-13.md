# 摄像头Demo - 问题修复记录

> 日期: 2026-07-13 | 项目: YoloDetector (.NET Framework 4.7.2, WinForms)

---

## 问题1: 摄像头画面卡住不动

**现象**: LibVLC 播放RTSP流，画面显示后卡住不动。

**根因**:
1. 网络缓存 `--network-caching=100` 过小，网络抖动时缓冲区溢出
2. 直播缓存 `:live-caching=500` 不足
3. 缺少流保活机制

**修复** (MainForm.cs):
```csharp
// LibVLC参数: 网络缓存 100→1000ms
string libvlcArgs = "--network-caching=1000";

// Media选项: 增大缓存 + 减少抖动
media.AddOption(":rtsp-tcp");
media.AddOption(":rtsp-frame-buffer-size=500000");
media.AddOption(":live-caching=1500");
media.AddOption(":network-caching=1500");
media.AddOption(":clock-jitter=0");
media.AddOption(":sout-keep");
```

**新增**: `streamKeepAliveTimer` 每10秒检查播放状态，卡顿时自动重连。

## 问题2: YOLO检测器初始化失败

**现象**: `"Microsoft.ML.OnnxRuntime.NativeMethods"的类型初始值设定项引发异常。`

**阶段1 - DLL缺失**: 项目使用 `Microsoft.ML.OnnxRuntime.Managed`（仅托管代码），缺少 native `onnxruntime.dll`。

**阶段2 - Opset不匹配**: ONNX Runtime 1.16.3 仅支持 Opset 19，YOLO模型使用 Opset 20。

**阶段3 - 架构不匹配**: 项目为AnyCPU/x86，ONNX Runtime 1.20.0 x86 版本缺少 `OrtGetApiBase` API。

**最终修复** (YoloDetector.csproj):
```xml
<!-- Managed → 完整包 -->
<PackageReference Include="Microsoft.ML.OnnxRuntime" Version="1.20.0" />
<!-- 统一为x64 -->
<PlatformTarget>x64</PlatformTarget>
```

## 问题3: 闪退 - 跨线程UI操作

**现象**: 点击"开始预览"后程序崩溃，异常信息：
```
System.InvalidOperationException: 线程间操作无效: 从不是创建控件"videoPanel"的线程访问它。
```

**根因**: LibVLC的 `MediaPlayer_Playing` 事件在**非UI线程**触发，直接调用 `StartYoloDetection()` → `videoPanel.Controls.Add(detectionOverlay)` 违规。

**修复** (MainForm.cs):
```csharp
private void MediaPlayer_Playing(object sender, EventArgs e)
{
    // ... 日志 ...
    // LibVLC事件在非UI线程触发，通过BeginInvoke切换到UI线程
    this.BeginInvoke(new Action(() => StartYoloDetection()));
}

private void StartYoloDetection()
{
    // 防御性检查：确保所有UI操作在主线程执行
    if (this.InvokeRequired)
    {
        this.Invoke(new Action(StartYoloDetection));
        return;
    }
    // ... UI操作 ...
}
```

## 问题4: 画面黑屏

**现象**: YOLO识别框可见，但摄像头画面完全黑屏。断开相机连接时画面恢复。

**根因**: WinForms的 `PictureBox` (托管HWND) 通过 `BringToFront()` 覆盖在 `VideoView` (LibVLC原生HWND) 上方。**Windows窗口管理中，托管控件永远无法渲染到原生控件之上**，`Color.Transparent` 只显示Form背景色，导致视频被遮挡。

**修复**: 用独立原生窗口 (`DetectionOverlayForm : Form`) 替代托管控件 (`PictureBox`)。
```csharp
// 之前（失败）：托管控件永远在VideoView下层
videoPanel.Controls.Add(detectionOverlay); // PictureBox

// 之后（成功）：原生窗口可以对等Z轴竞争
detectionOverlayForm = new DetectionOverlayForm(videoView);
detectionOverlayForm.Owner = this; // 跟随主窗口
detectionOverlayForm.Show();
```

**DetectionOverlayForm.cs** 关键技术:
- `TransparencyKey = Color.Magenta` — 洋红色完全透明
- `WS_EX_NOACTIVATE` (0x08000000) — 不抢焦点
- `WS_EX_TRANSPARENT` (0x00000020) — 鼠标穿透
- `ShowWithoutActivation => true` — 不激活窗口
- `SyncPosition()` — 主窗口移动/缩放时自动对齐

## 问题5: YOLO检测帧数据格式不匹配

**现象**: `System.NullReferenceException` at `_session.Run(inputContainer)`。

**根因**: OpenCV `frame.ToBytes()` 返回**原始BGR像素数据**，但 `PreprocessImage` 使用 `Image.FromStream()` 期望 JPEG/BMP 等图像格式。

**修复** (RtspFrameCapturer.cs):
```csharp
// 之前：原始像素数据
byte[] frameData = frame.ToBytes();

// 之后：编码为JPEG
Cv2.ImEncode(".jpg", frame, out byte[] frameData);
```

## 问题6: YOLO检测框坐标错误

**现象**: 识别框位置偏移、大小不正确。

**根因**:
1. YOLOv6 ONNX模型输出**归一化坐标 (0-1)**，代码按绝对像素值 (0-640) 处理
2. RTSP流的 `VideoCaptureProperties.FrameWidth/Height` 可能返回0，导致覆盖层缩放比错误

**修复1** (YoloV26Detector.cs) - 归一化坐标自动识别:
```csharp
// 自动检测坐标格式：归一化(0-1) vs 绝对像素值
bool isNormalized = (x < 2.0f && y < 2.0f && w < 2.0f && h < 2.0f);
if (isNormalized)
{
    x = x * _inputWidth;   // 归一化 → 模型输入空间 (640x640)
    y = y * _inputHeight;
    w = w * _inputWidth;
    h = h * _inputHeight;
}
// 模型输入空间 → 原始图像空间（去padding + 缩放）
x = (x - padX) * scaleX;
y = (y - padY) * scaleY;
```

**修复2** (RtspFrameCapturer.cs) - 从实际帧读取尺寸:
```csharp
// 之前：可能返回0
FrameWidth = (int)_capture.Get(VideoCaptureProperties.FrameWidth);

// 之后：读取第一帧获取实际尺寸
using (var testFrame = new Mat())
{
    for (int retry = 0; retry < 10; retry++)
    {
        if (_capture.Read(testFrame) && !testFrame.Empty())
        {
            FrameWidth = testFrame.Cols;
            FrameHeight = testFrame.Rows;
            break;
        }
        Thread.Sleep(200);
    }
}
```

**修复3** (DetectionOverlayForm.cs) - LibVLC letterboxing 黑边偏移:

> 这是坐标位置偏差的**最终根因**。YOLO 坐标本身是正确的，问题出在覆盖层渲染。

LibVLC **默认保持视频宽高比**。当 VideoView 尺寸比例与视频不匹配时，LibVLC 会在上下或左右添加黑边，实际视频内容只占 VideoView 的一部分。之前的覆盖层按 VideoView **全尺寸**计算缩放，导致盒子与视频内容错位。

```
示例: 1920×1080 (16:9) 视频 → 691×521 (4:3) VideoView

┌─────────────────────────┐ ← 覆盖层认为视频从这里开始 (y=0)
│██████ 黑边 66px ███████│
├─────────────────────────┤ ← 实际视频从这里开始 (y=66)
│                         │
│   实际视频内容 691×389   │   LibVLC保持16:9, 上下留黑边
│                         │
├─────────────────────────┤
│██████ 黑边 66px ███████│
└─────────────────────────┘
```

```csharp
// DetectionOverlayForm.OnPaint — letterboxing 自适应
float videoAspect = (float)_frameWidth / _frameHeight;
float viewAspect = (float)this.Width / this.Height;
float videoW, videoH, offsetX, offsetY;

if (videoAspect > viewAspect)
{
    // 视频更宽 → 上下黑边
    videoW = this.Width;
    videoH = this.Width / videoAspect;
    offsetX = 0;
    offsetY = (this.Height - videoH) / 2f;
}
else
{
    // 视频更高 → 左右黑边
    videoH = this.Height;
    videoW = this.Height * videoAspect;
    offsetX = (this.Width - videoW) / 2f;
}

// 盒子位置 = 黑边偏移 + 检测坐标 × 视频区域缩放比
x = offsetX + detection.Left * (videoW / _frameWidth);
y = offsetY + detection.Top  * (videoH / _frameHeight);
```

## 问题7: 检测灵敏度低 + 误识别

**现象**: YOLO检测框数量少，灵敏度不足；存在误识别。

**根因**:
1. `ConfidenceThreshold = 0.5` 过高，50% 门槛过滤掉了大量正确目标
2. `NmsThreshold = 0.45` 偏低，相近的检测框被过度合并

**修复** (YoloDetection/yoloConfig.json):
```json
{
  "ConfidenceThreshold": 0.3,   // 0.5→0.3 降低门槛提升灵敏度
  "NmsThreshold": 0.5,          // 0.45→0.5 减少框过度合并
}
```

**修复2** (YoloV26Detector.cs) - 重写Postprocess，自动识别输出格式:

YOLOv6-nano ONNX 导出**包含内置NMS处理**，输出格式为 `[x1, y1, x2, y2, confidence, classId]`（角点+已筛选），
而非原始预测 `[cx, cy, w, h, obj_conf, cls_0..cls_79]`（中心点+80类）。之前的代码把角点当成中心点处理导致框巨大。

```csharp
// Initialize时通过输出张量维度自动判断格式
if (dims[2] <= 7)
{
    _outputIsCornerFormat = true;   // 角点[x1,y1,x2,y2]格式
    _outputIsAlreadyScaled = true;  // 坐标已缩放，无需再次变换
}
else if (dims[2] >= 80)
{
    _outputIsCornerFormat = false;  // 中心[cx,cy,w,h]格式
    _outputIsAlreadyScaled = false; // 需要从模型空间缩放到原图
}

// 角点 → 中心转换
float fx = (x1 + x2) / 2;
float fy = (y1 + y2) / 2;
float fw = x2 - x1;  // 之前把这当宽度 → 实际是x2坐标！
float fh = y2 - y1;  // 之前把这当高度 → 实际是y2坐标！
```

**修复3** - 仅检测person + 过滤不合理框 + 限制数量:

```csharp
// 只要person (COCO classId=0)
if (classId != 0) return;
// 过滤太小/太大框
if (w < 10 || h < 10) return;
if (w > origWidth * 0.95f || h > origHeight * 0.95f) return;
// 最多5个框，按置信度排序
results = results.OrderByDescending(d => d.Confidence).Take(5).ToList();
```

**调参指南**:
| 参数 | 降低效果 | 升高效果 |
|------|---------|---------|
| `ConfidenceThreshold` | 检出更多目标，但误检增加 | 检测更精准，但可能漏检 |
| `NmsThreshold` | 保留更多重叠框 | 严格去重，框数量少 |

**模型升级方案**: 将 `yolo26n.onnx` (nano) 替换为 `yolo26s.onnx` (small) 或 `yolo26m.onnx` (medium)，文件放入 `YoloDetection/model/` 后修改 `ModelPath` 即可。

## 诊断技巧

1. **`📐坐标范围`** (前3帧): X/Y的min/max范围 → 判断坐标空间(归一化/模型空间/原图空间)
2. **`👤person#N`** (前3帧): 原始person候选值 → 验证格式(角点vs中心)、置信度、位置
3. **`[尺寸诊断]`** (每5秒): 捕获帧 vs Overlay尺寸 → 定位坐标偏移
4. **`★检测`** (每帧有人时): 最终检测结果的pos/size/conf → 验证渲染效果
5. **`☆帧`** (每30帧): 0目标时输出当前阈值 → 判断是否阈值过高

## 最终结论：YOLO模型现状（2026-07-14）

经过两天诊断，代码基础设施全部正确，但 **预训练YOLO模型在此监控场景下不可靠**。

### 已验证的模型

| 模型 | 最高置信度 | 能否跟踪人 | 误识别 | 评估 |
|------|-----------|-----------|--------|------|
| yolo26n.onnx (nano) | 0.012 | ❌ 框固定在左上角 | 背景特征 | 不可用 |
| yolo26s.onnx (small) | 0.011 | ❌ 框固定在右下角 | **鼠标光标** | 不可用 |
| yolo26s + ImageNet归一化 | 0.006 | ❌ 更差 | 鼠标光标 | 不可用 |

### 已确认正确的配置

- **预处理**: `/255` 归一化 (非ImageNet mean/std), RGB通道序, 640x640 letterbox padding
- **输出格式**: `[1,300,6]` NMS输出, **角点格式** `[x1,y1,x2,y2,conf,cls]`, **模型输入空间**(0-640)
- **坐标链路**: 角点→缩放(模型空间→原图2304x1296)→中心→person过滤→NMS→letterbox偏移→屏幕绘制
- **当前配置** (`yoloConfig.json`): `ConfidenceThreshold=0.005`, `NmsThreshold=0.35`

### 模型推荐（待尝试）

这些预训练COCO模型对监控视角泛化差。建议尝试:
1. **YOLOv8s / YOLOv8m** — 更新架构，COCO person mAP更高
2. **YOLOv11n / YOLOv11s** — 最新Ultralytics版本
3. **yolov8n-pose** — 带人体骨骼关键点，person检测更准
4. **专用行人检测模型** — 如在MOT/CrowdHuman数据集上fine-tune的模型
5. **自行训练** — 用本摄像头采集数据标注后训练，效果最好

操作: `.onnx` 文件放 `YoloDetection/model/` → 改 `yoloConfig.json` → 重启 → 看 `📐坐标范围` 确认格式

### 其他可排查方向

如果换了模型仍有问题，检查:
- 模型输出维度是否 `[1,N,6]` 或 `[1,N,7]`（NMS格式）还是 `[1,8400,85]`（原始预测）
- `📐坐标范围` 判断坐标空间（max≈640=需缩放, max≈2304=原图空间）
- `👤person#` 的宽高比例：宽≈高×0.3~0.6 则为角点格式，宽>高×1.5 则可能为中心格式

## 问题8: 项目架构优化 (2026-07-14)

### 优化清单

#### 8.1 编译输出目录统一

**问题**: `bin/` 和 `obj/` 两个目录分散，编译产物和中间文件混杂。

**修复**: 通过 `Directory.Build.props` 恢复默认的 `bin/` 和 `obj/` 目录（符合.NET项目标准约定）：

```xml
<!-- Directory.Build.props -->
<Project>
  <PropertyGroup>
    <MSBuildProjectExtensionsPath>obj\</MSBuildProjectExtensionsPath>
  </PropertyGroup>
</Project>
```

**结果**: 编译产物输出到 `bin/Debug/net472/`，中间文件输出到 `obj/`，结构清晰符合标准。

#### 8.2 YOLO源码泄露到输出目录

**问题**: 旧 csproj 的 `<Content Include="YoloDetection\**\*">` 将 `.cs` 源码文件也复制到了输出目录。

**修复**: 改为仅复制运行所需的配置文件：
```xml
<Content Include="YoloDetection\*.json">
<Content Include="YoloDetection\model\**\*">
```

#### 8.3 废弃文件清理

| 删除文件 | 原因 |
|----------|------|
| `YoloDetection/TransparentOverlay.cs` | 已废弃，被 `DetectionOverlayForm.cs`（原生窗口方案）替代 |
| `packages.config` | 旧 NuGet 格式残留，项目已迁移到 SDK-style `<PackageReference>`，且缺失 ONNX/OpenCV 包引用 |

#### 8.4 Bug修复

| Bug | 根因 | 修复 |
|-----|------|------|
| **Stopped事件重连后YOLO不启动** | `isPlayingTriggered` 在 `MediaPlayer_Stopped` → `StartVideoPreviewWithLibVLC()` 路径中未重置 | 在 `StartVideoPreviewWithLibVLC()` 开头添加 `isPlayingTriggered = false` |
| **FormClosing时序错误** | `StopYoloDetection()` 在 `yoloDrawTimer.Dispose()` 之后调用，但 `StopYoloDetection` 内部调用 `yoloDrawTimer.Stop()` | 调整顺序：先 `StopYoloDetection()`，再释放定时器 |
| **YoloDetectionService双重释放检测器** | `YoloDetectionService.Dispose()` 调用了 `_detector?.Dispose()`，但 `_detector` 由 `MainForm` 管理 | 移除 `YoloDetectionService` 中的 `_detector?.Dispose()` |
| **未使用字段残留** | `private bool _yoloFirstResultLogged` 声明后从未使用 | 删除 |

#### 8.5 性能优化

| 优化项 | 详情 |
|--------|------|
| **DetectionOverlayForm GDI缓存** | `Pen`/`Font`/`SolidBrush` 从每次 `OnPaint` 创建改为字段缓存，`OnPaint` 每100ms触发一次，避免高频GC压力 |
| **StreamKeepAliveTimer防重入** | 添加 `_isKeepAliveReconnecting` 标志，防止上一次重连未完成时再次触发（重连涉及 1s 延迟 + UI Invoke） |

#### 8.6 新增文件

| 文件 | 用途 |
|------|------|
| `.gitignore` | 忽略 `bin/`、`obj/`、`build/`、`.vs/`、`logs/`、模型文件等 |
| `Directory.Build.props` | 统一控制输出目录，所有项目共享此配置 |
